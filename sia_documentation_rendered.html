Document purpose

This document defines the purpose, scope, architecture, data design, integration contracts, security controls, operating model, verification strategy, and delivery plan for the Earth Event & Disaster Monitoring System (earth-emds). It gives an engineering team and academic evaluators full technical detail to implement, verify, and explain a coherent, production-ready system architecture.

The proposed system ingests NASA EONET v3 natural hazard event metadata, discovers related journalistic reporting through NewsAPI v2 (with resilient fallback to Google News RSS and UN OCHA ReliefWeb), and enriches affected-country demographic indicators through REST Countries v3.1. It stores normalized geometries in PostgreSQL with PostGIS (with SQLite WAL support for lightweight environments) and presents results through an interactive browser-based 3D CesiumJS globe alongside an accessible sidebar list. Article links are contextual matches because NewsAPI does not accept coordinates or verify that an article was written inside an event footprint. Country population density is a national-scale macro indicator, not an estimate of people exposed to a disaster.

Use boundary: This is an informational monitoring and educational learning system. It is not an emergency alerting, disaster prediction, casualty estimation, evacuation routing, or incident command service.

1. Executive summary

Earth Event & Disaster Monitoring System gives a user one place to explore selected natural events on an interactive globe and review reporting associated with the places and dates involved. The recommended production release combines a React 18 and CesiumJS client, a FastAPI backend, an asynchronous scheduled integration worker, PostgreSQL with PostGIS, and Redis for short-lived cache and job coordination.

NASA EONET v3 supplies event identity, category, source references, dates, magnitude where available, and point, line, or polygon geometries. The worker polls a rolling time window every 10 minutes and performs idempotent upserts so updates replace earlier observations without losing coordinate history. A versioned local country boundary layer (Natural Earth Admin 0 at 1:10m scale) maps event geometries to ISO country codes via ST_Intersects and a 100 km coastal buffer. REST Countries v3.1 supplies sovereign demographic profiles. NewsAPI's Everything endpoint is queried using event terms, place names, country context, language (en), and a date window within a 90-request/day budget. The backend ranks candidate articles using transparent rule-based evidence (+35, +25, +25, +15) and retains links to publishers.

The system is designed for timely exploration, not authoritative public warning. EONET notes that event extents may be approximate. NewsAPI offers text and date filters rather than geographic boundary search. REST Countries provides national population, area, and currency context, allowing the application to calculate indicative national density, but it cannot calculate local population exposure within an event footprint. These limits shape the data model, match labels, interface copy, and acceptance criteria.

2. System definition

2.1 Purpose and intended users

The product helps students, researchers, journalists, and interested members of the public explore where selected natural events are occurring and what reporting is available around them. It combines scientific event records, news discovery, and country reference data while preserving attribution to each source.

2.2 Goals

  • Show open and recent wildfires, severe storms, volcanoes, floods, and sea/lake ice on a manipulable 3D globe and accessible list.
  • Filter by category, time range, status (open/closed), text query, and map viewport bounds in under 2 seconds (p95).
  • Find candidate articles related by event terms, place or country terms, and publication time, with an explicit score breakdown for each association.
  • Show country name, ISO identifiers, currency, population, land area, and derived national population density with an as-of timestamp.
  • Preserve provenance, uncertainty, provider status, and freshness so map styling does not imply false ground-zero precision.

2.3 Non-goals

  • The system does not issue emergency alerts, predict hazards, estimate casualties, recommend evacuation, or replace official agencies.
  • It does not claim that an article is geographically inside an event polygon unless a future source supplies verifiable article coordinates.
  • It does not compute local population exposure, vulnerability, economic loss, or climate attribution from country totals.
  • It does not republish full copyrighted news articles or expose external API keys to client browsers.

2.4 Constraints and assumptions

3. Scope and user journeys

3.1 Primary user journey

  1. The user opens the globe and sees current open events grouped and color-coded by category with a visible last-updated time.
  2. The user narrows the view by event type, time range, status, or map bounds. The client requests filtered results from /api/v1/events.
  3. The user selects an event. The detail drawer queries /api/v1/events/{id} to display EONET title, category, geometry coordinate history, observation dates, magnitude if supplied, source links, and coordinate approximation caveats.
  4. The application displays Country Profile Cards associated with the event geometry, labeling the country boundary source and national scale of demographic density values.
  5. The article panel requests /api/v1/events/{id}/articles and lists candidate news items with publisher, publication time, link, and human-readable match reasons (+35, +25, +25, +15). The user clicks to open the source article in a new browser tab.

3.2 Secondary journeys

  • Search the event list by keyword or country name and open an event without manipulating the 3D globe.
  • Open an open-ocean or offshore event with no sovereign country match and still inspect the complete scientific record.
  • Open an event during upstream API downtime or rate-limit exhaustion and inspect cached records with an amber freshness banner.
  • Toggle 1-click Lite Mode to pause WebGL rendering on low-spec hardware while retaining complete list and drawer functionality.

3.3 System boundary

The application owns provider adapters, normalization, event-to-country spatial joins, article candidate ranking, persistence, and the user-facing API. NASA, NewsAPI, REST Countries, and Natural Earth remain external data authorities. The browser receives only application responses and never receives provider credentials.

5. Architecture overview

The system uses a decoupled modular architecture separating interactive user queries from asynchronous ingestion and enrichment pipelines. The browser communicates exclusively with the FastAPI application gateway. Provider integrations use backend adapters, and normalized records are stored in PostgreSQL with PostGIS.

Figure 1. Logical component architecture. The client browser communicates strictly with the FastAPI gateway.

5.1 Main request and data paths

Path Sequence
Interactive read Browser → FastAPI → Redis cache hit → (on cache miss: PostGIS spatial query) → normalized API response → globe and detail drawer.
Event synchronization Async Scheduler → EONET adapter → validation and normalization → idempotent event/geometry upsert → country containment → enrichment jobs.
Article enrichment Worker → Redis quota check (90/day) → NewsAPI adapter → candidate deduplication → rule-based scoring → article and match persistence.
Country enrichment Worker → PostGIS country lookup → REST Countries v3.1 adapter → profile normalization → versioned cache and retrieval time.

5.2 Deployment topology (Docker Compose)

  • frontend: Nginx 1.27 Alpine serving Vite production assets on internal port 8080 (mapped to host 3000:8080).
  • backend: FastAPI / Uvicorn running on host port 8000:8000.
  • worker: Async Python background worker running python -m app.worker on backend_net.
  • db: PostgreSQL 16 + PostGIS 3.4 running on internal port 5432 (volume pgdata).
  • redis: Redis 7 Alpine running on internal port 6379 (volume redisdata).

7. External integration specifications

7.1 NASA EONET v3

Base URL https://eonet.gsfc.nasa.gov/api/v3
Endpoints used /events?status=open to fetch open events; /events?status=closed&limit=100 for closed events.
Authentication None required (100% Free Public Scientific API).
Polling interval Every 10 minutes (600 seconds). Ensures newly visible events appear within 15 minutes of publication.
Fields consumed id, title, categories, geometry, sources, closed, magnitudeValue, magnitudeUnit.
Mapping rules closed is null for open events; missing magnitude stored strictly as null; multi-observation geometries preserved.

7.2 NewsAPI v2

Base URL https://newsapi.org/v2
Endpoints used /v2/everything
Authentication API key sent in X-Api-Key header (kept strictly server-side).
Query parameters q, searchIn=title,description, language=en, sortBy=relevancy, pageSize=15.
Quota management Hard daily cap of 90 requests/day in Redis (reserving 10 req on 100 req/day free Developer tier).
Enrichment cadence Enriched once upon initial event discovery and once at event closure.
Keyless fallback If budget exhausted or key missing, queries Google News RSS and attaches UN OCHA ReliefWeb disaster feeds.

7.3 REST Countries v3.1

Base URL https://restcountries.com/v3.1 (Corrected from draft PDF's erroneous "v5" label)
Endpoints used /alpha?codes={codes}&fields=name,cca2,cca3,population,area,currencies for batch lookups.
Authentication None required (100% Free Public Demographic API).
Density math Guarded: returns null if area ≤ 0 or missing, else round(population / area) as national average.

7.4 Local country boundaries

Dataset: Natural Earth Admin 0 Countries at 1:10m scale, pre-processed into GeoJSON (ne_admin0_countries.json). Features with iso_a3 = '-99' (e.g. Somaliland) are excluded from downstream REST Countries calls. Offshore points within 100 km are attached to the nearest coastal nation via ST_DWithin.

8. Data model and internal API

8.1 Physical schema (8 normalized tables — Part 1)

-- 1. Sovereign Country Boundaries (Natural Earth Admin 0 1:10m)
CREATE TABLE country_boundary (
    iso_a3 VARCHAR(3) PRIMARY KEY,
    iso_a2 VARCHAR(2),
    name VARCHAR(120) NOT NULL,
    geom GEOMETRY(MultiPolygon, 4326) NOT NULL,
    dataset_version VARCHAR(32) NOT NULL DEFAULT 'ne_10m_admin_0_v5.1.1',
    CONSTRAINT chk_valid_iso_a3 CHECK (iso_a3 <> '-99' AND length(trim(iso_a3)) = 3)
);
CREATE INDEX idx_country_boundary_geom ON country_boundary USING GIST (geom);

-- 2. Country Demographic Profiles (REST Countries v3.1)
CREATE TABLE country_profile (
    iso_a3 VARCHAR(3) PRIMARY KEY REFERENCES country_boundary(iso_a3) ON DELETE CASCADE,
    iso_a2 VARCHAR(2),
    name VARCHAR(120) NOT NULL,
    population BIGINT CHECK (population IS NULL OR population >= 0),
    area_sq_km DOUBLE PRECISION CHECK (area_sq_km IS NULL OR area_sq_km >= 0),
    population_density INTEGER, -- round(population / area_sq_km) or NULL
    currencies JSONB NOT NULL DEFAULT '{}'::jsonb,
    retrieved_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 3. Primary Scientific Hazards (NASA EONET v3)
CREATE TABLE event (
    id VARCHAR(64) PRIMARY KEY,
    title VARCHAR(300) NOT NULL,
    category VARCHAR(64) NOT NULL,
    status VARCHAR(16) NOT NULL CHECK (status IN ('open', 'closed')),
    closed_at TIMESTAMPTZ,
    sources JSONB NOT NULL DEFAULT '[]'::jsonb,
    first_seen_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    last_updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    news_enriched_on_open BOOLEAN NOT NULL DEFAULT FALSE,
    news_enriched_on_close BOOLEAN NOT NULL DEFAULT FALSE,
    CONSTRAINT chk_event_id_nonempty CHECK (length(trim(id)) > 0),
    CONSTRAINT chk_event_title_nonempty CHECK (length(trim(title)) > 0)
);
CREATE INDEX idx_event_category_status ON event (category, status);
CREATE INDEX idx_event_last_updated ON event (last_updated_at DESC);
CREATE INDEX idx_event_title_trgm ON event USING GIN (title gin_trgm_ops);

-- 4. Spatial Observations (Point, LineString, Polygon)
CREATE TABLE observation (
    id BIGSERIAL PRIMARY KEY,
    event_id VARCHAR(64) NOT NULL REFERENCES event(id) ON DELETE CASCADE,
    observed_at TIMESTAMPTZ NOT NULL,
    geom GEOMETRY(Geometry, 4326) NOT NULL,
    magnitude_value DOUBLE PRECISION,
    magnitude_unit VARCHAR(32),
    CONSTRAINT uq_event_observation UNIQUE (event_id, observed_at),
    CONSTRAINT chk_valid_geom CHECK (ST_IsValid(geom))
);
CREATE INDEX idx_observation_geom ON observation USING GIST (geom);
CREATE INDEX idx_observation_event_time ON observation (event_id, observed_at DESC);

-- 5. Event-to-Country Spatial Join Table
CREATE TABLE event_country (
    event_id VARCHAR(64) NOT NULL REFERENCES event(id) ON DELETE CASCADE,
    iso_a3 VARCHAR(3) NOT NULL REFERENCES country_boundary(iso_a3) ON DELETE CASCADE,
    match_method VARCHAR(32) NOT NULL CHECK (match_method IN ('intersects', 'coastal_proximity')),
    PRIMARY KEY (event_id, iso_a3)
);
CREATE INDEX idx_event_country_iso ON event_country (iso_a3);

8.1 Physical schema (8 normalized tables — Part 2)

-- 6. Deduplicated News Articles (NewsAPI v2 / Fallback Feeds)
CREATE TABLE article (
    canonical_url TEXT PRIMARY KEY,
    original_url TEXT NOT NULL,
    title TEXT NOT NULL,
    description TEXT,
    publisher VARCHAR(160) NOT NULL,
    published_at TIMESTAMPTZ NOT NULL,
    retrieved_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
CREATE INDEX idx_article_published_at ON article (published_at DESC);

-- 7. Explainable Match Evidence (algorithm_version = 'v1')
CREATE TABLE article_match (
    event_id VARCHAR(64) NOT NULL REFERENCES event(id) ON DELETE CASCADE,

    algorithm_version VARCHAR(16) NOT NULL DEFAULT 'v1',

9. Data processing, matching and demographic pipelines

9.1 Explainable news scoring rubric (algorithm_version = 'v1')

To eliminate opaque black-box NLP/LLM behavior and provide complete transparency, candidate articles are scored on a deterministic 100-point rubric:

  • +35 pts — Event Title Phrase Match: A distinct token from the EONET event title appears in the article headline (e.g. "Matched event title phrase 'Kilauea' (+35)").
  • +25 pts — Hazard Category Keyword Match: A specific hazard term (wildfire, storm, typhoon, volcano, flood, etc.) appears in the headline or description (e.g. "Matched hazard category keyword 'volcano' (+25)").
  • +25 pts — Country / Place Name Match: The matched country or administrative territory name appears in the title or description (e.g. "Matched country/location 'United States' (+25)").
  • +15 pts — Temporal Proximity Match: The article publication timestamp is within the active event observation window (±7 days) (e.g. "Published within event observation window (+15)").

Confidence Thresholds: Strong (≥ 70 pts), Moderate (45–69 pts), Weak (25–44 pts). Articles scoring below 25 points are discarded.

9.2 Guarded population density formula

def calculate_population_density(population: int | None, area_sq_km: float | None) -> int | None:
    if population is None or area_sq_km is None or area_sq_km <= 0:
        return None
    return round(population / area_sq_km)

The UI displays the result with the mandatory label: "National Average (people/km²)".

10. Security and responsible presentation

10.1 Key isolation and network hardening (NFR-04)

  • Zero Client Secret Exposure: NEWSAPI_KEY and database passwords reside strictly in server-side .env configurations loaded by FastAPI and the worker. Client browser network bundles contain zero credentials.
  • Read-Only Public Endpoints: All public routes accept only GET requests. Mutating routes (POST /sync) are shielded from external clients.
  • Strict Parameter Validation: Pydantic v2 validates all query inputs. Coordinate bounding boxes outside [-180..180, -90..90] return HTTP 422.
  • Docker Network Segmentation: Database port 5432 and Redis port 6379 communicate across an internal bridge network (backend_net) and are not exposed to the public host.

10.2 Mandatory user interface disclaimers (NFR-10)

1. Satellite Geometry Caveat: "Event coordinates and perimeters from NASA EONET v3 represent approximate satellite/agency observations and may reflect reporting latency. Do not use for local emergency navigation or life-safety decisions."
2. National Population Density Caveat: "Population density is a national macro-level average calculated from REST Countries v3.1 (Population ÷ Area in km²) and does not measure local population exposure inside the hazard footprint."
3. Contextual News Matching Caveat: "News reports are matched contextually using keyword, location, and date proximity rules—not by verified GPS coordinates within the disaster perimeter."

11. Reliability and operations

11.1 Graceful degradation model (NFR-03, NFR-09)

  • Last Valid Snapshot Preservation: If NASA EONET, REST Countries, or NewsAPI is unreachable or returns HTTP 429/5xx, the worker aborts overwriting and preserves the stored database snapshot.
  • Freshness Banner: The frontend displays an amber banner showing the exact age of cached data and the last successful sync timestamp.
  • NewsAPI Quota Defense: When the 90-request/day budget is reached, NewsAPI calls are paused and the keyless fallback pipeline (Google News RSS + ReliefWeb) automatically takes over.

12. Deployment and delivery

  • Multi-Stage Slim Images: Frontend built with Node.js and served on nginx:1.27-alpine; Backend and Worker built on python:3.11-slim.
  • Non-Root Execution: Application processes execute as an unprivileged user (USER appuser, UID 10001).
  • Container Hardening: Configured with security_opt: ["no-new-privileges:true"], cap_drop: ["ALL"], and read_only: true root filesystems with ephemeral tmpfs: [/tmp].
  • Lite Mode Optimization: CesiumJS uses requestRenderMode: true (rendering only upon camera interaction), reducing idle GPU usage by ~90%. A 1-click header toggle allows switching to 2D list-only exploration.

13. Verification strategy

  • Layer 1 (Unit Tests): Zero-I/O tests for EONET title trimming, null magnitude preservation, URL canonicalization, density math, and scorer.py weights (+35, +25, +25, +15).
  • Layer 2 (Contract Tests): Recorded JSON fixtures testing EONET v3, REST Countries v3.1, and NewsAPI v2 adapters under HTTP 401, 429, and 503 errors.
  • Layer 3 (Spatial Integration Tests): Real PostGIS queries asserting ST_Intersects and coastal ST_DWithin (100 km) country matching, plus performance benchmarks verifying < 2s response for 2,000 events (NFR-01).
  • Layer 4 (Frontend & E2E Tests): Vitest component tests and Playwright E2E suites verifying keyboard accessibility (@axe-core/playwright), 3D globe interactions, and outage simulation.

14. Implementation roadmap and acceptance

The system followed an iterative Agile Scrum lifecycle structured across four sprints:

  • Sprint 1 (FR-01 to FR-03): EONET v3 ingestion adapter, normalizer, idempotent PostGIS upsert queries, and 10-minute worker loop.
  • Sprint 2 (FR-07 to FR-09): Natural Earth Admin 0 1:10m spatial import, ST_Intersects matching, REST Countries v3.1 demographic profiling, and guarded density math.
  • Sprint 3 (FR-10 to FR-12, FR-14): NewsAPI v2 integration, Redis quota tracking (90 req/day), rule-based scoring (algorithm_version 1), and keyless fallback.
  • Sprint 4 (FR-04 to FR-06, FR-13, FR-15): FastAPI read-only gateway, React 18 + CesiumJS 3D interface, Lite Mode, accessible sidebar list, and E2E verification.

15. Architecture decision records (ADRs)

  • ADR-01 (Async Python Worker vs Celery): Adopted a native asyncio scheduler inside a dedicated container, eliminating heavy Celery dependencies and simplifying Docker operations.
  • ADR-02 (Server-Side PostGIS vs Client GIS): Executed spatial intersections server-side to prevent client browsers from downloading heavy shapefiles.
  • ADR-03 (Explainable Rule Scorer vs Black-Box AI): Replaced opaque NLP/LLM models with a verifiable point-based scoring rubric (+35, +25, +25, +15).
  • ADR-04 (Redis Budget Guard & Multi-Tier News): Capped daily NewsAPI requests at 90 and implemented keyless Google News RSS and ReliefWeb fallbacks.
  • ADR-05 (On-Demand WebGL & Lite Mode): Added demand-driven rendering and a 1-click toggle to ensure usability on low-spec student laptops.

16. Glossary

Admin 0: Sovereign national boundary level. • BBOX: Viewport bounding box [minLon, minLat, maxLon, maxLat]. • CesiumJS: WebGL 3D virtual globe library. • EONET: NASA Earth Observatory Natural Event Tracker. • EPSG:4326: WGS 84 coordinate reference system. • GiST: Generalized Search Tree spatial indexing in PostgreSQL. • Lite Mode: 2D list-and-drawer view pausing WebGL rendering. • PostGIS: Spatial extension for PostgreSQL. • RFC 7946: GeoJSON specification.
